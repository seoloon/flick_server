# Minimal environment, panel on by default, README: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove `FLICKSYNC_ADMIN_TOKEN`, shrink `.env.example` to what a first start needs (full reference moves to `docs/configuration.md`), turn the panel on by default in compose, and rewrite the README (new wordmarks, Flick Server as a feature utility with modules).

**Architecture:** Two code removals (server `admin_token`/config, panel token resolution and env check), each with its tests; then configuration docs and `.env.example`; then compose and the wording fixes in the other docs; then the README. Docs are the bulk of it: every task ends with `grep` and link checks instead of new runtime code.

**Tech Stack:** Rust 2024 (config, admin API, tests), Next.js 16 / TypeScript with the Node 22 test runner (panel), Docker Compose, Markdown.

**Spec:** `docs/superpowers/specs/2026-10-10-env-compose-readme-design.md` (earlier specs: `2026-10-07-module-lifecycle-settings-design.md`, `2026-10-08-panel-settings-design.md`, `2026-10-08-logs-design.md`)

## Global Constraints

Every task's requirements include these:

- No new dependency: `Cargo.toml`, `Cargo.lock`, `panel/package.json`, `panel/package-lock.json` stay unchanged.
- The working tree may hold untracked `panel/AGENTS.md` and `panel/CLAUDE.md` (generated by `next dev`): never stage them. Stage only the files a task names, by explicit path (no `git add -A`, `git add .`, `git commit -a`).
- Commit messages end with the line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- After every Rust task: `cargo fmt --check`, `cargo clippy --all-targets` (no warnings) and `cargo test` pass. After every panel task, from `panel/`: `npm test` (0 failures) and `npm run typecheck` (no output); a task touching `src/app`, `src/components` or `src/styles` also passes `npm run build`.
- The admin token stays `hex(HMAC-SHA256(PANEL_PASSWORD, "flick-admin-api-v1"))`; the test vector is `derive("correct horse battery staple") = 602faf385fbedfdd2399872d5e5ec4359027f10a59806d0d6c4b598faf591011`.
- Docs: plain, short sentences; British spelling in the panel UI, same voice as the existing README in the README; no emoji in new technical docs (the README keeps its existing section emoji); relative links must resolve.
- Historical specs and plans under `docs/superpowers/` are not edited (they record past decisions), except the two new files of this sub-project.
- Never touch `checkpoint.md`.

## Review Focus

1. A `.env` that still has `FLICKSYNC_ADMIN_TOKEN` (valid or too short) and a good `PANEL_PASSWORD`: server and panel both start, the line is ignored, no error and no warning about it (Task 1: `a_leftover_admin_token_variable_is_ignored`; Task 2: `a leftover FLICKSYNC_ADMIN_TOKEN is ignored`).
2. A `.env` with only the legacy token and no `PANEL_PASSWORD`: the admin API is off (404) and the server says so; the panel refuses to start with the `PANEL_PASSWORD` message (Task 1: `the_legacy_token_alone_no_longer_enables_the_admin_api`; Task 2: existing `PANEL_PASSWORD` problem test).
3. A first install with an empty `.env`: `docker compose config` shows `ENABLE_WEB_PANEL=true` for `panel` and no restart loop beyond five tries (Task 4).
4. `ENABLE_WEB_PANEL=false` in `.env`: the panel service gets `false` (the `${ENABLE_WEB_PANEL:-true}` default only applies when unset or empty) (Task 4).
5. A variable removed from `.env.example` is still documented, with its default and meaning, in `docs/configuration.md` (Task 3: a script check that every `FLICKSYNC_*` / `FLICKDD_*` name found in the old `.env.example` appears in the new file).
